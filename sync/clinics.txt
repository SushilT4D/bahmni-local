# Fleet-wide residue ledger.  clinic_id:offset
#
# The increment (10) is set by docker-compose.override.yml's
# --auto-increment-increment; this file sets only the per-node OFFSET.
# scripts/configure-pk-offsets.sh looks up the row whose key equals this
# node's BHS_LOCATION (case-insensitive, first match wins).
#
# ALLOCATION IS FLEET-WIDE AND MUST BE UNIQUE PER NODE.  The offset is the
# strided residue that makes every row's origin computable from its own
# primary key, which is what L-008 (per-row single-writer ownership) and
# L-010 (a collision-free sync key) rest on.  Two nodes sharing an offset
# mint colliding primary keys and there is no way to tell the rows apart
# afterwards.  Never reuse or reassign a residue on a node that has already
# written rows.
#
#   cloud    : 10   (residue 0)
#   manpur   : 1
#   bedawal  : 2
#   ghated   : 3    - lab clinic 2
#   rawach   : 4    - lab clinic 1
#   bagdunda : 5
#   kojawada : 6
#   azure    : 7    - TEST clinic on an Azure VM, not a BHS clinic
#   morwal   : UNALLOCATED - 12,882 patients, cannot sync until assigned
#
# 8 and 9 are free.  Counting Morwal, 9 of 10 are spoken for while azure lives.
# Per-clinic non-secret identity (MRN prefix, site number) is in sync/fleet/<slug>.env;
# the hub endpoint in sync/hub.env; the installer composes its answers from them.
